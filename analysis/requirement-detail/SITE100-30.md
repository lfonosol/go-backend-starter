# SITE100-30 — Add progressive reveal

> "The handover site gains progressive reveal, exposing the additional context made available to the model beneath what a human reader consumes."

MoSCoW and Status live in the shared Scope Tracker sheet, and the requirement's phase in `.planning/ROADMAP.md` — **look them up there; this card does not restate them.** The quotes below are the workshop-corpus record.

**Sources:** change record `CR-040` · locus `S-02 capture`

## What this is for

A handover package now carries two audiences at once: the person reading a page and the model being given far more context than that page shows. Today only the first is visible, so the depth behind a page is invisible to the client and impossible to review. This puts the second layer underneath the first, openable and closeable, so a reader sees a clean page and can look beneath it when they want to. It is the first concrete step toward the role-based views the practitioner wants eventually, and it changes what a client can verify about how their material is being used.

## The evidence

**What the source says.** From the same capture passage quoted in full on [SITE100-20](SITE100-20.md): *"I really just want to have a client view and a progressive reveal to show the additional context we would make available for the AI."*

**The reasoning on the register.** It depends on the marking rule's record and on the clean-up pass's per-area decision. It changes the docs and detail modules, the shell template and the chrome stylesheet — **so the reveal is a rendering change over a recorded marking, not a content change.**

**Judgment calls that bear on it.** **The role-based destination is recorded so its absence reads as a boundary.** The capture names four eventual views: developer, client, CPO and AI. **The near-term scope is the client view plus this reveal, and the full set is the eventual goal.** Role-based views beyond the client view are out of scope for this milestone and carry no register row. **A plan that builds a view selector is building the wrong thing.**

## Open items and watch-outs

- **It is last in a hard chain and cannot be started early.** The clean-up pass decides, the marking rule records, this builds. The three cannot be reordered or run in parallel.
- Exposing the model's context to a client reader is a disclosure decision as much as a rendering one. What sits beneath a page is now visible to whoever holds the site password.
